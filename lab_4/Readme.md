# Перемножение матриц на GPU с использованием технологии CUDA

## 1. Аппаратная и программная конфигурация
* **Вычислительный узел:** кластер Самарского университета (`n243`, очередь `batch`).
* **Графический ускоритель:** NVIDIA Tesla M2070 (5301 МиБ, архитектура Fermi, `sm_20`).
* **Программный стек:** CUDA 8.0 (`nvcc -O3 -std=c++11`), планировщик задач Slurm.

## 2. Порядок запуска на кластере
1. Подключение к внутренней сети вуза через VPN (`vpn.ssau.ru`) и вход на управляющий узел `login2` по SSH.
2. Проверка очередей и модулей: `sinfo -o "%12P %10a %6D %15G %N"` (выявлены GPU-узлы `n[243,250]` с ресурсом `gpu:tesla:2`) и `module avail` (выбран `cuda/8.0`).
3. Конвертация формата строк скрипта (`sed -i 's/\r$//' cuda_job.sh`) и настройка параметров Slurm (`#SBATCH --partition=batch`, `#SBATCH --gres=gpu:tesla:1`, `module load cuda/8.0`).
4. Постановка задачи в очередь (`sbatch cuda_job.sh`) и мониторинг выполнения (`squeue -u $USER`).

## 5. Выводы
* **Низкая эффективность блока 4×4:** блок из 16 потоков вдвое меньше размера аппаратного варпа NVIDIA (32 потока), из-за чего половина вычислительных линий простаивает, а производительность падает в ~3.8 раза (9.35–10.73 GFLOPS).
* **Оптимальный блок 16×16:** конфигурация на 256 потоков (8 полных варпов) обеспечивает максимальную производительность (пик **41.87 GFLOPS** при $N=1200$) и минимальное время расчёта начиная с $N=400$.
* **Снижение скорости на блоке 32×32:** предельный для архитектуры Fermi блок (1024 потока) уступает блоку 16×16 на 7–12% из-за высокой нагрузки на регистровую память мультипроцессоров и неполных граничных блоков сетки.
* **Насыщение производительности:** при $N \ge 1200$ накладные расходы на запуск ядра нивелируются, и производительность выходит на плато ~41.2–41.9 GFLOPS, упираясь в пропускную способность глобальной памяти GPU.
